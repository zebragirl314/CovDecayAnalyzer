- **M1 is half right.** `isSingular` is TRUE in only **12.9%** of null fits
  (31 of 240; Clopper-Pearson 95% CI 8.9% to 17.8%), far below the 50%

### Generator checks (all pass)

12 expectations, 0 failures.

   tau +1.0%; sigma +0.4%.
2. Idealized calibration: Type I 0.040, KS p = 0.54 (above).
3. Positive control (Delta = 3e-5, n = 4): power 1.000.
4. Path equivalence (atom path vs per-base `load_all_samples`, including a

   generated first, caller RNG untouched, 5 kb and 1 kb share the same truth.

   `log_norm_cov` by 7e-16.

statistics): `data.table::fwrite` has no `digits` argument here (check 4);
check 6 originally demanded p-values equal to 1e-8, but they agree only to

near-boundary REML surface for data that differ at 1e-16. I loosened that
tolerance to 1e-4 and left a comment saying why. That is itself a small
symptom of M1.

## Decisions needed from Carly before A2-2

1. **M1 comparator arm.** Singular rate is low, but the correlation is near -1
   in 97% of fits. Should A2-2 run the random-slope-only comparator
   (`(0 + distance_scaled | sample)`)? My recommendation: yes as an
   informational arm, since it is cheaper than the primary and answers whether
   the random intercept earns its keep. Calibration looks fine without it, so
   this is not urgent, and it would not change the primary model.
2. **How to scope the paired 1 kb arm.** Full pairing on every dataset costs
   about 20x the whole 5 kb study at the same R. Options: (a) 1 kb at the
   reference geometry only; (b) 1 kb at reduced R (for example 1,000 for Type I
   and 300 for power); (c) both, plus capping 1 kb at `L <= 238 kb` since
   500 kb at 1 kb is 15 to 57 s per fit; (d) move to HPC (Q4). This is also the
   Q4 trigger: with 1 kb everywhere, Tier 2 does not fit in "a few overnight
   runs" locally.
3. **Collapse premise (factual).** The prompt says a different `s_ref` "should
   change tau_eff by a known factor." In this generator it does not:
   `tau_eff^2 = tau^2 + sigma_bin^2 / Sxx` has no `s_ref` in it, because a
   shared `s_ref` shifts every sample's slope equally and median normalization
   removes the level. I did not stop for this because only one pilot item
   depends on it and the pilot's output is the same under either reading. I ran
   both an `s_ref` pair (ratio 1, tests that power does not depend on `s_ref`)
   and a `tau` pair (ratio known). Question: is `s_ref` meant to be a nuisance
   axis that should not matter, or should `tau` scale with `s_ref` (for
   example a coefficient of variation) so it does?
4. **`pbkrtest`.** `test_decay_slopes()` needs it at runtime for Kenward-Roger
   but `DESCRIPTION` lists it only under Suggests. In a clean library my first
   fit returned "pbkrtest package required for Kenward-Roger's method". This is
   the existing "`pbkrtest` Imports/Suggests" item on the NOTES punch list;
   it is now an observed failure, not a tidiness question. I did not touch
   `DESCRIPTION`.
