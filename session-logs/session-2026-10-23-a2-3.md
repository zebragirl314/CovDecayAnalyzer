## What changes the paper's argument or Tier 2 scope

1. **The "mixed model beats two-stage" claim, as I flagged in A2-2, is now
   confirmed to be Welch vs pooled.** Under balance the LMM makes the same
   decisions as a pooled two-stage on per-sample slopes. The honest balanced-design
   claim is "LMM matches the classical slope ANOVA/t-test and beats KW at small n",
   with the Welch arm labelled as a conservative alternative. A real mixed-model
   advantage can only appear where the LMM and slope-ANOVA differ: unbalanced
   groups, unequal bins per sample, dropouts (S2). **Proposal:** put the
   unbalanced designs (PLAN 4.1: 2 vs 5, 3 vs 8) and S2/S3 in Tier 2 with
   `two_stage_pooled` as a benchmark; that is where the paper's LMM argument
   will be won or lost. Conversely, pooled t at G = 2 assumes equal slope variance
   across groups, so S3(b) is where Welch could beat both. This is a framing
   decision for you; I changed nothing in the spec.
2. **M3:** the one positive signal is gone. Tier 2 anchor work can be one
   confirmatory sweep rather than a dedicated mechanism study. It is still only
   tested at G = 2, n = 5.
3. **1 kb:** keep restricted to the reference cells. Median 7.7 s per LMM fit at
   1 kb (Tier 1 had 5.9 s; the prompt assumed 2.8 s); 8.7 CPU-hours for these 4,000
   datasets, so the A2-3 run took 1 h 20 min, not about 1 hour.
4. **KW chi-square Q7 labels are discreteness, not misbehavior.** The exact null
   rejection rate of chi-square KW at G = 2, n = 5 is 0.0556 (enumerated), so the
   observed 0.053 to 0.059 is on target and "liberal" by the Clopper-Pearson rule at
   R = 5000 is expected. Tier 2 should report the exact null rate next to KW cells.
5. **Permutation Dunn is validated only on the random-permutation path at
   G = 3, n = 5** (all 500 fits `random_perm`: 756,756 assignments exceeds the 2e5
   enumeration cap). The enumeration path is covered by unit tests (G = 3, n = 3 and
   G = 2), not by a simulation cell. At G = 2 it equals the omnibus permutation p
   by construction (checked, 50/50 in the dry run).

## Caveats and deviations

1. **1 kb pairing covers 200 replicates, not 1000.** Tier 1's 5 kb reference cells
   have replicates 1 to 200; I joined by scenario_id and replicate_id as instructed
   and did not rerun 5 kb. The paired differences therefore rest on 200 datasets
   (CIs about +/- 0.02 for the LMM near the boundaries, wider at Delta_std 0.5);
   the full-1000 vs 200 comparison is unpaired (also in the table, wider CIs). A 5 kb
   run on replicates 1 to 1000 for those four cells would cost minutes and give the full
   paired comparison; say if you want it.
2. **The slope-only cell runs all arms**, because every cell runs every arm; the
   primary LMM numbers at that cell are a by-product (0.0506 above), not requested.
3. **Replicates 1 to 200 of each reused scenario are the same datasets as Tier 1**
   (seeds derive from scenario and replicate IDs). The R = 500 validation cells are not
   independent of Tier 1 at those 200.
4. **Added cells:** pooled validation at G = 2, n in {2, 3} (Delta_std 0 and 1,
   R = 500). The prompt's n = 5 cells cannot distinguish pooled from Welch (they
   already agree there); n <= 3 is where the arms differ and where the LMM question
   lives. Also G = 3, n = 5, Delta_std 0 for an actual Type I of the permutation Dunn.
5. The Dunn validation "Type I" requested at Delta_std 1 would be power; the table
   reports both Delta_std 0 and 1.
6. Warning: two cells (`dunn_perm;pooled`, `slope_only;pooled`) merged where scenario
   and bin coincide, taking the larger R; their family label is joined with `;`.
